## Confirmed bugs and changes

1. **P1-AUDIT-01 — authorization revoked during restore left protected UI visible.** `App.sync()` set access to allowed after authorize, but pull/push failures with `permission-denied` or `unauthenticated` only set an error. Two new tests failed before the fix. The outer catch now sets access to denied and closes an open form for those codes while preserving IndexedDB/outbox. Both tests pass after the fix. Firestore Rules already denied server access; this fixes the client access gate.
2. Added real-emulator regression for lost commit acknowledgement, repeated retries, coalesced offline revisions, audit counts, clean independent-device restore and account isolation. Existing emulator test formatting was normalized without changing its assertions.
3. Added production PWA offline create/edit/new-page regression, second browser-context seeded restore, auth account-switch regression and exact Bangkok midnight tests.
4. Initial new PWA test closed the page immediately after clicking Save, before IndexedDB commit confirmation; it observed revision 1. Fixed the test to await dialog closure (the app closes it after commit), then close the page. This is a test synchronization correction, not proof that an unacknowledged write survives forced termination.
5. Initial repository format check found existing formatting failures in `src/daily.ts`, `src/DailyPanel.tsx` and `src/test/daily.test.ts`. Applied Prettier only; no daily workflow behavior was changed. README/QA now link to this report so historical limitations are not mistaken for the current implementation.
6. First full check exposed an existing intermittent browser-test race: the evidence workflow selected the next files before the first save completed, and then timed out clicking the disabled save button after the previous operation cleared selection. Added assertions that each saved original is visible in the persistent upload queue before selecting the next batch or drawing the signature. A targeted repeat then exposed inconsistent synthetic touch drawing (2 PASS / 1 FAIL). Added an enabled/stable canvas action check and a browser animation-frame acknowledgement between CDP touch moves so Chromium delivers individual stroke events. The corrected targeted test passed three consecutive runs. No arbitrary sleeps or increased timeout were added. The failed runs remain recorded; a fresh full check is required after the correction.
