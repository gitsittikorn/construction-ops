# UX/UI สำหรับผู้ใช้ที่ไม่ถนัดคอมพิวเตอร์

ผู้ใช้อนุมัติให้ปรับหน้าด้านใน ลำดับเมนู ระยะห่างปุ่ม/ช่องเลือก/หัวข้อ และเพิ่มโครงการ DEMO พร้อม Commit/Push เมื่อ 2026-11-09 ห้ามเปลี่ยนข้อมูลจริงหรืออ้างว่า UI ใหม่แก้การเชื่อม Google Sheets จริงแล้ว

ใช้ [Vercel Web Design Guidelines skill](https://github.com/vercel-labs/agent-skills/blob/main/skills/web-design-guidelines/SKILL.md) และ [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md) เป็นแนวทางตรวจโค้ดด้าน labels, keyboard/focus, typography, error recovery และ layout อ่านต้นฉบับก่อนใช้ในงานนี้ ไม่มี UX skill ติดตั้งใน cloud catalog และไม่ได้ติดตั้งหรืออ้างว่าใช้ปลั๊กอิน Figma

## หลักที่ต้องรักษา

อัปเดตมือถือ 2026-11-10: ดู [MOBILE_WEB_READINESS.md](MOBILE_WEB_READINESS.md). ใช้ native dialog ให้พื้นหลังไม่รับโฟกัส คืนโฟกัสเมื่อปิด และรักษาฟอร์มผ่านหมุนจอ ช่องกรอกใน modal และหน้าเลือกบริษัทต้องมีขนาดอักษรอย่างน้อย 16 px บนจอสัมผัส ไม่จำกัด browser zoom. ปุ่ม Logout ต้องเข้าถึงได้เมื่อส่วน profile ของ Sidebar ถูกซ่อน ผล Chromium จำลองไม่แทน Safari/iPhone จริง

- จัดเมนูตามงาน: งานประจำวัน → เตรียมข้อมูล → ตรวจงานและสรุป → ดูแลข้อมูลและบัญชี คงชื่อเมนูและสิทธิ์ตามบทบาทให้ผู้ใช้เดิมยังหาเจอ
- อธิบายแต่ละหน้าว่าใช้ทำอะไร ด้วยภาษาไทยสั้น ๆ มีวิธีใช้ 3 ขั้นตอนที่เปิดอ่านได้ ไม่บังคับให้ผ่านบทเรียนก่อนทำงาน
- ข้อความในฟอร์ม 14–16 px ช่องกรอกจอมือถือ 16 px ข้อความอธิบาย 14 px หัวข้อส่วน 20 px ใช้สีเข้มพอให้อ่านง่าย
- ช่องเลือก/ช่องกรอกมี label ชัดเจน ระยะ label ถึง control อย่างน้อย 8 px กลุ่มปุ่ม/ตัวกรองห่างกัน 16 px ส่วนงานห่างกัน 20–24 px ห้ามใช้ช่องว่างข้อความแทน CSS gap
- ปุ่มหลักบอกสิ่งที่จะบันทึก เช่น บันทึกยอดรถ/บันทึกเรตราคา ปุ่มรองไม่แย่งความเด่น ห้ามใช้เพียงไอคอนโดยไม่มีชื่อที่เข้าถึงได้
- การกระทำทั่วไปอยู่ก่อน รายละเอียดเฉพาะทางใช้หัวข้อเปิดอ่าน เช่น กรองเพิ่มเติม/อ่านยอดรายงานอย่างไร คงข้อความเตือนสำคัญและ error ที่มองเห็นได้
- แสดงสถานะเป็นภาษาไทย ตัวเลขสรุปอ่านง่ายและไม่เดายอดที่ยังไม่ทราบ ปุ่มล้างตัวกรองต้องช่วยกลับจากผลค้นหาว่างหรือช่วงวันที่ผิด โดยไม่แก้ข้อมูลต้นฉบับ
- ใช้คีย์บอร์ดได้ มี focus และลิงก์ข้ามไปเนื้อหา เมนูบนจอเล็กเลื่อนในแถบของตัวเอง ตารางกว้างเลื่อนภายในกรอบ ห้ามซ่อน overflow เพื่อกลบข้อมูลที่ถูกตัด
- ข้อมูลตัวอย่างต้องมีชื่อ DEMO และคำอธิบายว่าเป็นข้อมูลสมมติ สร้างเมื่อกดปุ่มเท่านั้น ใช้ธุรกรรมและคิวปกติของบัญชี ห้ามสร้างไฟล์/หลักฐานที่อ้างว่า Google ยืนยันแล้ว ห้ามลบ/เขียนทับข้อมูลเดิมเพื่อสาธิต

## ลองข้อมูลทั้งโครงการ

หน้า **ภาพรวม → สร้างโครงการ DEMO และดูรายงาน** สร้างโครงการ `DEMO · โครงการถมดินตัวอย่าง` แล้วเปิดรายงานที่กรองเฉพาะโครงการนี้ให้ทันที เมื่อมีแล้ว ปุ่มจะเปิดข้อมูลเดิม ไม่สร้างซ้ำหรือรีเซ็ตสิ่งที่แก้ไว้

ข้อมูลใช้วันที่ปัจจุบันตามเวลาไทยและ 4 วันก่อนหน้า: รถ 2 คัน คนขับ 2 คน แหล่งดิน ทีม ชนิดดิน งานรายวัน 5 วัน รวม **80 เที่ยว / 1,200 m³** มี 1 แถวที่ยอดรายงานไม่ตรงและ 1 แถวรอกรอกยอด ไม่มีหลักฐานหรือการยืนยัน/ปิดวันปลอม

เรตราคาสมมติ: รายรับ 80 บาท/m³ ค่ารถ 400 บาท/เที่ยว ค่าคนขับ 100 บาท/เที่ยว ค่าใช้จ่ายรวม 6,800 บาท คิดเป็นรายรับ 96,000 ค่ารถ 32,000 ค่าคนขับ 8,000 และส่วนต่างประมาณการ **49,200 บาท** ยังไม่ใช่การจ่ายเงินจริง งานสำรวจ 10 × 10 เมตร ระดับเดิม 0 แบบ 1 เมตร ให้ถมแน่น **100 m³** จากค่าที่สมมติ ไม่ใช่ใบรับรองสำรวจ

ไป **โครงการ → DEMO → ดู / แก้ไข → สถานะโครงการ → ฉบับร่าง → บันทึกข้อมูล** ได้ รายงานเก่ายังเปิดดูได้และการกด DEMO ซ้ำไม่เปลี่ยนกลับเป็นโครงการใช้งาน เจ้าของ/ผู้จัดการสร้างได้ พนักงานไม่มีปุ่มหรือสิทธิ์สร้างชุดนี้

ข้อมูลถูกสร้างในพื้นที่ที่ใช้อยู่เท่านั้น: local mode อยู่ในเครื่อง บัญชีบริษัทเข้าคิวซิงก์ตามสิทธิ์ปกติ ไม่มีการย้ายข้อมูลระหว่าง local กับ Google โดยอัตโนมัติ รายงานรวมทุกโครงการจะเตือนเมื่อมี DEMO; เลือกโครงการจริงก่อนส่งรายงานใช้งานจริง

## ข้อจำกัดของการยืนยัน

ตรวจด้วย unit/domain tests, emulator และ browser desktop/tablet/mobile แยกจากการสัมภาษณ์ผู้ใช้จริง การใช้งาน Google/Drive/Sheets จริง และอุปกรณ์ Android จริง ไม่มีการรับรองคะแนน usability หรือ WCAG ทั้งระบบจากการแก้ครั้งนี้ ดูผลที่รันจริงใน ROADMAP_PROGRESS.md และ UX_UI_REPORT.md
